## Round 1 — verdict: APPROVE WITH CHANGES

Three **blocking** conditions before implementation could start:

1. **`IProcessRunner` must be in the design.** The plan had no process-execution seam, so none of the acceptance criteria were unit-testable. Only the concrete `NodeProcessRunner` may touch `spawn`.
2. **`ScriptSelectorService` collapsed to a pure function.** A class + DI registration + interface for a `switch` is over-engineering; house precedent does it inline.
3. **State store moved to `workspaceState` behind `SettingsManager`.** The plan's "local workspace settings file" violated the AGENTS.md hard rule and would have committed machine-specific state shared across developers.

Also raised 11 gaps to close in the implementation plan: concurrency/re-entrancy, cancellation, progress, missing `requirements.json` as a silent no-op (not an error), telemetry limits, command-triggered activation only, disposables, path joining, the self-contradictory acceptance criterion #10, explicit `bash` invocation, and the `jq` dependency.

## Round 3 — verdict: APPROVE WITH MINOR CHANGES

**All three blocking conditions confirmed satisfied.** Notably, `getPrerequisitesValidated()` has zero call sites — the cache is write-only and provably cannot short-circuit the check step, which is the correct shape.

Full pre-review checklist passed (re-entrancy guard, cancellation token threaded to spawn, `withProgress`, `notConfigured` handling, telemetry scope, disposables, explicit `bash`, PowerShell fallback chain, path containment, consent).

**Four should-fix items raised:**

1. `ConfirmationService.confirm()` fails **open** — dismissing the modal returns `"accepted"`. Pre-existing and repo-wide, but now gating workspace-controlled script execution.
2. Cancellation leaks descendant processes — killing `pwsh`/`bash` does not kill `winget`/`brew`/`apt`.
3. Cancelling during `ensureEnvironment` reports the wrong error ("No usable PowerShell host was found").
4. UTF-8 corruption across chunk boundaries — `chunk.toString("utf8")` per `data` event.

Plus nits: `stat` before read, marker first-vs-last and case-sensitivity, phantom `NEXKIT_NON_INTERACTIVE`, `OutputBuffer` slicing characters against a byte cap, blank `name`/`command`, missing `capabilities.untrustedWorkspaces`.

**Accepted residual risk (recorded, not fixed):** the scripts themselves `eval`/`Invoke-Expression` the version command from `requirements.json` on every run. No extension-side hardening closes that — only Workspace Trust does.
